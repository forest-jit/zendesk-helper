Start here

This guide describes the local v0.7.12 interface; deployment is on hold. If your installed version is v0.7.8, use Zendesk’s profile picture → Appearance → Light mode until the update arrives. The new build has been checked with both native appearances and never changes your saved Zendesk appearance.

  1. Open the extension from Chrome’s toolbar.
  2. Use the On / Off switch. Off restores Zendesk’s native interface; your settings are kept.
  3. Choose a theme or open Settings. Changes save immediately.

Themes and previews

Follow your Mac’s appearance Choose System light / dark.
Make your own theme Open Settings → Appearance → Create or edit a theme. Name it and pick Page background, Fields & messages, Text, Buttons & links, and Internal notes. Colors and hex values both work.
Try it on the ticket first Click Preview on ticket. Zendesk and enabled Harvest styling update temporarily. Stop preview or close the Settings tab to return to your saved theme.

Each theme starts with five colors. Borders, hover states, and other shades are derived from them. Unreadable color combinations cannot be saved; adjust text against both backgrounds if the editor reports a contrast problem.

Match Harvest to your theme

Harvest styling is off by default. Choosing a theme does not turn it on.

  1. Open Jones IT Zendesk Helper from your browser’s toolbar.
  2. Open Settings → Harvest, then click Match Harvest to theme.
  3. Allow access to platform.harvestapp.com when asked.
  4. Check that the button says Harvest theme on. If the permission prompt was interrupted, reopen Settings and click Match Harvest to theme again if needed.
  5. Reload the Harvest panel using its reload icon, or refresh Zendesk after protecting your drafts.

Set this up separately in each browser/profile and when switching between Store and unpacked installations. If Harvest stays white, check the setting and allowed site access. The helper changes styling only, not timer values or time entries. Other embedded apps keep their own interface.

Read a ticket

  • One reading flow: conversation history and the reply box share the left scrollbar. Scroll to the bottom to write. The right sidebar scrolls independently. The desktop columns have no divider line.
  • Short history: the latest five messages appear by default. View full conversation at the top of the scrolling history reveals the rest; Collapse earlier messages returns to five. Turn off Settings → Replies & reading → Start with the latest five messages to show all loaded history.
  • Compact fields: Requester, Assignee, Followers, Tags, Ticket Code, Priority and Status stay in the main sidebar. Additional fields opens the rest.
  • Images: images taller than320 CSS pixels at their normal inline size become compact previews. Short banners, logos and wide, short screenshots stay inline. Hover or click a preview for the full image; Escape closes it.
  • Titles: the automatic-title setting uses the selected company and requester: Company - Requester - Issue. It keeps the issue text and avoids repeated prefixes. Changes save with the ticket, not in the background. Undo restores the previous title and turns automatic updates off.

If company or requester information is missing, the helper leaves the title alone. It does not guess names. Keep the issue after the first two “ - ” separators when editing a structured title.

Email threads and readability

Quoted email means earlier correspondence copied inside one received message. It can contain the only copy of a request or an inline answer. The helper does not check for duplicates.

  1. Find Earlier email included in this message at a recognized quote boundary. It starts open.
  2. Read the earlier section. When you are finished with it, choose Hide quoted email.
  3. A short excerpt identifies the hidden section. Choose Show quoted email to read it again.

This only folds part of one message. View full conversation reveals older ticket messages instead. Unknown structures and quote-only messages remain visible. Original text, links and images stay in place, and hidden quoted text stays in raw exports. Off restores the native view.

Simplify email formatting has been removed. It reset widths, table spacing and fills; wrapping could make a message taller without helping. It did not summarize or remove repeated replies.

With a theme selected, text with insufficient contrast against a solid message background receives readable display ink. Readable authored colors and branded email panels stay intact. Complex image backgrounds remain original.

Other reading controls

  • Closed tickets: Status shows Closed and is disabled when Zendesk reports that the ticket cannot be edited. Helper Send and Save actions are hidden.
  • Native SLA badge: a negative time such as -23h indicates an overdue SLA target. It is separate from ticket status; Zendesk’s metric details identify the target.
  • Desktop columns: the helper uses a fixed sidebar width. Turn the helper Off to return to native column resizing.
  • Long Harvest references: notes and reference text use bounded scroll areas so the timer stays open and fields have more room. The helper does not change their values.

Reply and save

Action How
Switch reply mode in one click Click the Public reply or Internal note side of the two-part control. The selected side is highlighted. It uses Zendesk’s native selector behind the scenes; turning the helper Off restores that selector.
Carry your text across modes In Settings → Replies & reading, enable Use the same draft when switching reply modes. Text and formatting carry when the other draft is empty or still matches the last carried copy. A different destination draft is kept, with a message explaining the conflict. Separate drafts remain the default.
Send a reply or note Click Send, or press ⌘ + Enter while typing in the composer. Check the displayed public/internal mode first.
Save fields without sending Click Save changes, or press ⌘ + Enter while focused in the sidebar. The helper protects and restores the active text draft during the field save. Save stays disabled when nothing changed.

On other platforms, use Ctrl + Enter.

Quiet feedback

Successful copying, draft carry, settings changes and exports do not add a confirmation banner. The changed control, draft or Chrome download shows the result. Errors, draft conflicts, recovery instructions, saving progress and title Undo remain visible when needed.

If something interrupts a save

The helper keeps a local recovery copy. It will not overwrite a newer draft. If you see Save recovery copy, use it before continuing; this saves the held versions locally and keeps the current draft. Check the result before retrying an unconfirmed save.

Queued attachments must finish or be removed before carrying a draft or saving only fields. Carrying a draft never sends it.

Queue and copying

  • Copy ticket: click once to copy a linked ticket number. Rich-text apps receive a clickable link; plain-text apps receive a Markdown link. There is no format menu.
  • Queue refresh: Settings → Replies & reading offers 10, 15, 30 or 60 seconds, or Off. The default is 15 seconds. It uses the native view refresh; ticket pages never reload.
  • Refresh pauses: while you type, select tickets, open a menu/filter/dialog, interact recently, go offline, or hide the tab. The queue shows whether it is running or paused.

Zendesk’s native viewing and editing indicators remain unchanged. The helper no longer adds its own activity badge. See Zendesk’s agent collision guide for the native behavior.

Help test it

Keep real customer tickets read-only. Use #209867 for draft edits, field changes, saves or sends.

  1. Copy a ticket and paste into your usual editor. Confirm that the ticket number links to the correct ticket.
  2. Try different public and internal drafts with the shared-draft setting on. A distinct destination must survive; conflicts should explain what happened.
  3. On the test ticket, save a sidebar field while a reply draft exists. Confirm that the field saves without sending or losing either draft.
  4. On messy real tickets, read a quoted section before hiding it, then show it again. Try tall-image previews and check text, links, image access, colors and scroll position.
  5. Try your usual screen size, zoom, keyboard and assistive tools. Report the ticket number, theme, action and what you expected.

Export for local AI

  1. Open the toolbar popup on a ticket. Check Current ticket: #…, then click Export ticket. It downloads JSON without saving fields or sending a draft. Closing the popup does not cancel the request.
  2. In the project folder, open Start Local Review.command. Choose the JSON, then Create summary.
  3. Review the summary, conclusion, recorded actions and verification, and reusable notes. C1 means the first exported message, C2 the second. Supporting excerpts and Check cited messages help compare the result with redacted originals.
  4. Check personal information, missing media and image interpretations. Choose Download Notion draft only after review.
  5. Import the reviewed Markdown into your chosen documentation page. Nothing is published automatically.

The separate local reviewer needs Ollama with downloaded mistral:latest and qwen2.5vl:3b models. The Chrome Web Store extension does not install it. See docs/DOCUMENTATION_HANDOFF.md for setup and command-line options.

Raw exports include original rendered ticket information, including hidden messages and quotes. Unloaded history and unavailable media are reported. Redaction can miss personal information; image observations remain unverified. Processing uses local models and does not send ticket contents to a hosted AI service or upload to Notion. Close and export remains available after choosing Solved; that action saves the ticket before downloading.

Installation and updates

Install from the Chrome Web Store. Development copies use the unzipped extension folder through chrome://extensions → Developer mode → Load unpacked. After an update, protect your drafts, reload the extension, and refresh Zendesk once. Team installation may need your organization’s approval.

For detailed local-processing and team-install instructions, see docs/DOCUMENTATION_HANDOFF.md and docs/DISTRIBUTION.md in the project folder.
